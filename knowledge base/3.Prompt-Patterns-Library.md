What reusable Prompt Engineering patterns can I use, when should I use them, and how do I adapt them to different tasks?

# Prompt Patterns Library

> A practical library of reusable Prompt Engineering patterns for designing, testing, refining, and evaluating Generative AI prompts.

---

## Purpose

Prompt patterns are reusable structures for solving recurring problems when working with Generative AI.

Instead of designing every prompt from scratch, a Prompt Engineer can recognize the type of problem and select an appropriate pattern.

This library organizes reusable patterns relevant to:

- Prompt Engineering
- Generative AI
- Large Language Models (LLMs)
- AI-assisted writing
- Analysis and decision support
- Structured output
- In-context learning
- Few-shot prompting
- Preference-driven refinement
- AI evaluation
- RAG
- Physics AI applications

The patterns in this library are intended to be **adapted to the task**, not copied mechanically.

---

# 1. What Is a Prompt Pattern?

A prompt pattern is a reusable structure for addressing a recurring Prompt Engineering problem.

A pattern describes:

```text
Problem
   ↓
Prompting Strategy
   ↓
Reusable Structure
   ↓
Expected Behavior

===============================================================================================================================================

2. Pattern Selection Principle

Do not assume that a more complicated prompt is automatically better.

Use:

The simplest pattern that reliably solves the task.

A useful progression is:

Simple Task
    ↓
Clear Instruction
    ↓
Add Context
    ↓
Add Constraints
    ↓
Add Structure
    ↓
Add Examples
    ↓
Add Evaluation / Refinement

Only add complexity when it improves the output.

4. Persona Pattern
Problem

The AI produces a generic voice or perspective rather than the perspective required by the user.

Strategy

Define the role, experience, perspective, audience, and communication characteristics expected from the AI.

Basic Structure
ROLE:
Act as a [specific role].

EXPERTISE:
You have expertise in [domain].

AUDIENCE:
You are communicating with [audience].

VOICE:
Use [specific characteristics].

TASK:
[Task]
Example
Act as an experienced secondary-school Physics educator.

Explain the concept to Grade 10 students using clear language,
real-world examples, and conceptual explanations before equations.

Avoid unnecessary technical jargon.
Best Used When
Consistent voice matters.
Domain expertise matters.
The audience has specific needs.
The task requires a particular perspective.
Risk

A vague persona such as:

"Act as an expert."

may not provide enough information to meaningfully influence the output.

5. Task + Context Pattern
Problem

The AI receives an instruction but does not have enough context to perform it accurately.

Strategy

Separate the task from the information required to complete it.

Structure
TASK:
[What the AI must do]

CONTEXT:
[Relevant background]

INPUT:
[Information to process]

REQUIREMENTS:
[Important constraints]

OUTPUT:
[Expected result]
Example
TASK:
Create a Physics explanation.

CONTEXT:
The students are studying momentum for the first time.

INPUT:
[Concept or lesson content]

REQUIREMENTS:
Use one real-world example and explain the concept before
introducing the equation.

OUTPUT:
A student-friendly explanation.
Best Used When

The model needs background information that is not obvious from the task itself.

6. Constraint Pattern
Problem

The AI produces output that is too long, too vague, too technical, or otherwise outside the desired boundaries.

Strategy

Explicitly define constraints.

Common Constraints
Word count
Audience
Tone
Number of items
Required sections
Prohibited content
Level of technical detail
Source restrictions
Example
Write the explanation in fewer than 100 words.

Use language appropriate for Grade 9 students.

Include one real-world example.

Do not use advanced mathematical notation.
Best Used When

The task has measurable requirements.

Important Principle

Constraints should be specific enough to evaluate.

7. Template Pattern
Problem

The AI generates correct content but uses an inconsistent structure.

Strategy

Provide the structure that the AI should follow.

Basic Structure
# [Title]

## Summary
[Content]

## Key Findings
[Content]

## Recommendations
[Content]

## Next Steps
[Content]
Example Use Cases
Reports
Lesson plans
Research summaries
Evaluations
Business documents
Educational resources
Best Used When

Consistency and repeatability are important.

8. Few-Shot Pattern
Problem

A written instruction alone does not sufficiently demonstrate the desired behavior.

Strategy

Provide examples using explicit input-output pairs.

Structure
Input:
[Example input]

Output:
[Desired output]

Input:
[Example input]

Output:
[Desired output]

Now process:

Input:
[New input]

Output:
Example
Input:
Concept: Newton's First Law
Audience: Grade 10

Output:
[Desired example]

Input:
Concept: Conservation of Momentum
Audience: Grade 10

Output:
[Desired example]

Now process:

Input:
Concept: Work-Energy Theorem
Audience: Grade 10

Output:
Best Used When
Output style is difficult to describe.
The task requires a particular transformation.
Classification behavior needs demonstration.
Formatting must be consistent.
Quality Requirements for Examples

Examples should be:

Correct
Relevant
Consistent
Representative
Diverse enough to show the intended behavior
9. Preference-Driven Refinement Pattern
Problem

The AI produces a technically acceptable answer, but it does not match the user's preferred quality, style, or priorities.

Strategy

Define explicit preferences and use them to refine the desired output.

Structure
PREFERENCES:

1. [Preference]
2. [Preference]
3. [Preference]

AVOID:

1. [Undesired characteristic]
2. [Undesired characteristic]

REFINEMENT GOAL:
[Describe what should improve]
Example
Preferences:

- Clear rather than academic
- Conceptual before mathematical
- Concise rather than repetitive
- Real-world examples when useful

Avoid:

- Generic textbook language
- Unnecessary jargon
- Repetition
Best Used When

The problem is not simply correctness but quality alignment.

10. Multi-Perspective Pattern
Problem

A complex decision or plan may look different depending on the analytical perspective used.

Strategy

Analyze the same input using multiple distinct lenses.

Structure
LENS 1:
[Perspective]

LENS 2:
[Perspective]

LENS 3:
[Perspective]

LENS 4:
[Perspective]

CROSS-CUTTING FINDINGS:
[Patterns appearing across multiple lenses]

RECOMMENDATIONS:
[Actions based on the combined analysis]
Example Lenses
Risk
Feasibility
Stakeholder
Opportunity
Cost
Technical
Educational
Ethical
Best Used When

A single analytical framework may overlook important perspectives.

Important Principle

The lenses should be genuinely different.

Changing only the wording of the same analysis does not create meaningful diversity.

11. Taxonomy Pattern
Problem

A collection of responses or comments contains recurring themes but is difficult to organize.

Strategy

Cluster the information into themes and then organize those themes into a hierarchy.

Structure
Top-Level Theme
├── Sub-theme
│   ├── Specific Pattern
│   └── Specific Pattern
└── Sub-theme
Example Instruction
Identify recurring themes in the dataset.

Group related responses into sub-themes.

Organize the result as an ASCII taxonomy tree.

Do not create categories that are not supported by the data.

Place genuine outliers under an Unclassified branch.
Best Used For
Survey responses
Social media comments
Customer feedback
Qualitative datasets
Open-ended responses
12. Pathway Generation Pattern
Problem

A user has a starting point and a goal but several intermediate steps are missing.

Strategy

Generate multiple routes using genuinely different strategies.

Structure
STARTING POINT:
[Current state]

KNOWN STEPS:
[Existing steps]

GOAL:
[Desired state]

PATHWAY 1:
[Strategy]
[Steps]
[Trade-offs]

PATHWAY 2:
[Different strategy]
[Steps]
[Trade-offs]

PATHWAY 3:
[Different strategy]
[Steps]
[Trade-offs]

COMPARISON:
[Compare pathways]
Example Strategy Types
Fastest
Lowest risk
Lowest cost
Resource-efficient
Highest learning
Most collaborative
Most conservative
Most innovative
Important Principle

Three pathways should not simply rearrange the same steps.

They should represent genuinely different strategies.

[Identify type]

PURPOSE:
[Identify purpose]

COMPANION 1:
[Document / Analysis]
Gap addressed:
Information used:

COMPANION 2:
[Document / Analysis]
Gap addressed:
Information used:

...

[Missing information]
Best Used For
Business plans
Project plans
Policy documents
Technical proposals
Project charters
Strategic documents
Important Principle

The companion pieces should add something new.

They should not simply summarize the original artifact.

A creator has content but wants to identify additional groups that may be interested in it.

Strategy

Analyze the themes, topics, and tone of the source content and infer audience segments from those patterns.

Structure
CONTENT THEMES:
[Themes]

TOPICS:
[Topics]

TONE:
[Tone]

AUDIENCE SEGMENT 1:
Why they may be interested:
Confidence:

AUDIENCE SEGMENT 2:
Why they may be interested:
Confidence:

...

MOST PROMISING SEGMENT:
[Segment]

[Unsupported assumptions]
Best Used For

Survey responses
Blog posts
Educational content
Thought leadership
Important Principle

Audience predictions should be based on evidence in the supplied content rather than unsupported demographic assumptions.

15. Structured Reporting Pattern
Problem

The AI needs to transform source information into a consistent report.

Strategy

Combine:

Source data
A defined output template
Formatting requirements
References or footnotes
Structure
SOURCE DATA:
[Facts / data]

REPORT TEMPLATE:
[Required structure]

FORMATTING:
[Markdown / table / headings]

SOURCE REFERENCES:
[Required citation or footnote method]
Best Used For
Data reports
Scientific summaries
Research reports
Technical documentation
Structured analysis
Important Principle

16. Evaluation Pattern
Problem

An AI output needs to be judged consistently rather than subjectively.

Strategy

Give the evaluator explicit criteria and scoring rules.

Structure

AI OUTPUT:
[Response]

EVALUATION CRITERIA:
1. [Criterion]
2. [Criterion]
3. [Criterion]

SCORING:
[Scale]

EVIDENCE:
[Evidence for each judgment]

OVERALL RESULT:
[Result]

RECOMMENDATION:
[Improve / Accept / Reject]

17. Hallucination-Mitigation Pattern
Problem

The AI may generate information that is plausible but unsupported by the available data.

Strategy

Explicitly restrict the model to the supplied information and require it to identify gaps.

Structure
SOURCE:
[Trusted information]

RULES:
- Use only information supported by the source.
- Do not invent missing facts.
- Identify information gaps.
- Label assumptions explicitly.
- Distinguish facts from inference.

TASK:
[Task]
Best Used When
Factual accuracy matters
Source data is limited
The model must not fabricate information
Domain expertise is involved
18. Grounded / RAG Pattern
Problem

The AI needs information beyond the immediate prompt.

Strategy

Retrieve relevant information from an external knowledge source and provide it as context.

Structure
USER QUESTION:
[Question]

RETRIEVED CONTEXT:
[Relevant information]

INSTRUCTIONS:
Use the retrieved context to answer the question.

GROUNDING RULES:
- Prefer the supplied context.
- Do not invent missing information.
- Identify insufficient information.
- Distinguish source information from inference.

OUTPUT:
[Required format]
Typical Workflow
Question
   ↓
Retrieve
   ↓
Filter Relevant Information
   ↓
Provide Context
   ↓
Generate
   ↓
Evaluate
19. Prompt Refinement Pattern
Problem

The first prompt does not produce the desired output.

Strategy

Use the output as evidence for improving the prompt.

Workflow
Initial Prompt
      ↓
Generate Output
      ↓
Evaluate Output
      ↓
Identify Failure
      ↓
Modify Prompt
      ↓
Generate Again
      ↓
Compare
Refinement Questions

Ask:

What did the model do correctly?
What did it misunderstand?
Which instruction was ambiguous?
What information was missing?
Which constraint was ignored?
Would an example help?
Would a clearer output structure help?
Does the prompt contain unnecessary complexity?
Important Principle

Do not automatically make the prompt longer.

Make it clearer and more effective.

20. Constraint + Evaluation Pattern
Problem

A prompt contains requirements, but the model may not reliably satisfy them.

Strategy

Define the constraints and then explicitly evaluate the output against them.

Structure
TASK:
[Task]

CONSTRAINTS:
1. [Constraint]
2. [Constraint]
3. [Constraint]

OUTPUT:

Before finalizing, verify:
- [Constraint 1 satisfied]
- [Constraint 2 satisfied]
- [Constraint 3 satisfied]

This can improve compliance with clearly defined requirements.

21. Input → Transformation → Output Pattern
Problem

The AI must transform information while preserving important properties.

Strategy

Explicitly define what enters the system, what transformation should occur, and what should be produced.

Structure
INPUT:
[Source]

TRANSFORMATION:
[What to do]

PRESERVE:
[What must remain unchanged]

OUTPUT:
[Desired result]
Example Uses
Summarization
Rewriting
Translation
Classification
Data transformation
Educational adaptation
22. Analyze → Synthesize → Recommend Pattern
Problem

A task requires more than simple analysis.

Strategy

Separate the workflow into:

Analyze
   ↓
Synthesize
   ↓
Recommend
Structure
ANALYSIS:
Identify important findings.

SYNTHESIS:
Combine related findings and identify patterns.

RECOMMENDATIONS:
Convert the most important findings into actionable steps.
Best Used For

Business analysis

23. Cross-Cutting Findings Pattern
Problem

Multiple analyses may identify related issues, but the common patterns are difficult to see.

Strategy

After completing separate analyses, identify findings that appear across multiple perspectives.

Structure
ANALYSIS 1
ANALYSIS 2
ANALYSIS 3
ANALYSIS 4
       ↓
CROSS-CUTTING FINDINGS
       ↓
PRIORITIZED ACTIONS
Why It Matters

A weakness appearing in several independent analyses may deserve greater attention than an isolated observation.

27. Pattern Quality Checklist

Before adding a new pattern to this library, ask:

 Does it solve a recurring Prompt Engineering problem?
 Is the problem clearly defined?
 Is the strategy distinct from existing patterns?
 Can the pattern be reused across tasks?
 Is the structure clear?
 Can the pattern be adapted?
 Does it have a clear use case?
 Are limitations or risks identified?
 Does it avoid unnecessary complexity?

A pattern should not be added simply because it is a different way of wording the same prompt.

28. Pattern vs Prompt Template

These terms should not be confused.

Pattern

A reusable strategy or structure.

Example:

Multi-Perspective Pattern

Template

A reusable prompt implementation with placeholders.

Example:

Analyze [PLAN] using [LENS 1], [LENS 2], and [LENS 3].

Therefore:

Pattern
   ↓
Template
   ↓
Specific Prompt
29. Pattern vs Technique

A technique is a method used to improve prompting behavior.

A pattern is a reusable structure for solving a recurring problem.

For example:

Technique:
Few-shot prompting

Pattern:
Few-Shot Pattern

Template:
Input: [example]
Output: [example]
...

The boundaries can overlap, so terminology should be used consistently within the project.

33. Pattern Evaluation

A successful pattern should be evaluated based on the behavior it produces.

Useful criteria include:

Criterion	Question
Accuracy	Is the output correct?
Relevance	Does it address the task?
Instruction Following	Were requirements followed?
Consistency	Does the pattern produce stable behavior?
Flexibility	Can it adapt to different inputs?
Efficiency	Does it add unnecessary complexity?
Reliability	Does it reduce common failure modes?
Usability	Can another person understand and reuse it?
34. Important Principle: Patterns Are Not Magic

A prompt pattern does not guarantee a correct output.

Model behavior can vary according to:

Model capabilities
Task complexity
Input quality
Context quality
Example quality
Ambiguity
Domain complexity
Evaluation criteria

Therefore:

A pattern should be treated as a tested strategy, not as a guarantee of model performance.

37. Final Principle

The purpose of a Prompt Patterns Library is not to collect as many prompt patterns as possible.

Its purpose is to help a Prompt Engineer answer:

"What type of problem am I solving, which reusable pattern fits that problem, and how can I adapt and evaluate that pattern for my specific task?"

A strong pattern is:

Reusable + Clear + Adaptable + Testable + Purpose-Driven
