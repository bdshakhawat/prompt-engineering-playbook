# Prompt Engineering Case Study

## Case Study 1: Reproduce the Lecture's "Same Prompt, New Conversation" Test

**Goal:** Directly observe that a single AI output is not a fixed, definitive answer by running the identical prompt multiple times in separate conversations.

### Method
1. Submit this prompt in a new conversation:
   > "Write an email announcing my new course on Advanced Prompt Engineering on Coursera."
2. Start a brand-new conversation (not a follow-up) and submit the exact same prompt again, unchanged.
3. Repeat a third time in another new conversation.

### Expected Observation
Each of the three outputs should differ noticeably — different opening lines, different structure, different emphasis — despite the prompt being word-for-word identical each time.

### Key Takeaway
This confirms the lecture's central claim: there is no single "correct" output waiting to be generated. Each run produces one possible perspective among many, which means stopping after the first attempt means accepting an arbitrary draw rather than a considered choice.

## Case Study 2: Apply "Exploiting Generation" to a Physics Explanation

**Goal:** Test whether generating multiple options for a physics explanation produces a genuinely better result than accepting the first one.

### Method
1. Generate a first explanation:
   > "Explain why objects in projectile motion follow a curved path, for a 10th grade student."
2. In a new conversation, submit the identical prompt again.
3. In a third new conversation, submit it once more.

### Comparison Questions to Answer
- Which version uses the clearest real-world analogy?
- Which version most directly addresses the common misconception that horizontal and vertical motion affect each other?
- Is there a sentence or example in one version that's stronger than the equivalent part in another?

### Result: Merging
Combine the strongest analogy from one version with the clearest misconception-correction from another into a single, merged explanation — testing the lecture's claim that merging can produce something better than any single generated version.

### Key Takeaway
Having three options instead of one forced an actual evaluation process — identifying strengths and weaknesses — rather than passive acceptance. The final merged version was shaped by my own judgment about what works best for my students, not by whichever draft happened to generate first.

## Case Study 3: Measure the "Cost" of Generating Multiple Options

**Goal:** Test the lecture's claim that the additional time cost of generating multiple options is small relative to the quality gain.

### Method
1. Time how long it takes to generate one output for a task (e.g., a parent email about an upcoming physics lab).
2. Time how long it takes to generate two additional versions of the same prompt.
3. Time how long it takes to compare all three and select or merge a final version.

### What to Notice
- The generation time for additional outputs is typically a small fraction of the total time spent on the task.
- The comparison and merging step, while requiring active thought, is where the actual quality improvement happens — this is time well spent, not wasted overhead.

### Key Takeaway
The lecture explicitly rejects "time saved" as a meaningful metric (e.g., dismissing claims like "AI saved me 11 minutes"). This exercise confirms that the real trade-off isn't much time for much quality — it's a small amount of additional time for a disproportionately large gain in quality and originality.

## Case Study 4: Deliberately Test the Risk of Multiple Options in a Physics Context

**Goal:** Because physics content requires factual accuracy, test whether generating multiple options ever introduces a *plausible but incorrect* version alongside correct ones.

### Method
1. Generate three separate explanations of a physics concept prone to common misconceptions (e.g., "why does a heavier object not fall faster than a lighter one in a vacuum").
2. Carefully fact-check each version, not just compare them for tone or clarity.

### Expected Risk
Because each generated version is an independent "perspective," it's possible for one version to contain a subtle factual inaccuracy that looks just as polished and confident as the correct versions.

### Key Takeaway
Exploiting generation multiplies the number of perspectives to choose from — but it does not multiply their accuracy. Fact-checking must still be applied to *every* generated option individually, not just to whichever one is ultimately selected or merged. This is an important refinement to the lecture's principle when applying it to a factual, technical subject like physics rather than to a general email.

---

## Key Takeaway From This Case Study

Exploiting generation works because comparison, not generation itself, is where quality improvements come from. Generating multiple options is nearly free; the real investment is in actively evaluating them — identifying what's genuinely better, and why — rather than defaulting to whichever version happened to appear first. In a physics context specifically, that evaluation step must include a factual accuracy check, since more options means more chances for an error to appear, not fewer.
