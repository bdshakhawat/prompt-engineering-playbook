Module 2, Lesson 4 Notes
Separating Evaluation from Generation: Building Independent Metrics to Assess Options
Learning Objectives

After completing this lesson, I should be able to:

Explain why separating the generation of options from the generation of evaluation criteria produces a more thorough, less biased evaluation.
Understand how to prompt an AI to generate evaluation metrics for a task without generating solutions to that task.
Recognize the value of using generative AI to produce evaluation dimensions, not just solution options.
Apply the "template pattern" to format evaluation output consistently.
Understand how to combine independently generated options and independently generated metrics into a single evaluation step.
Recognize how this technique can be extended into structured outputs like tables, evaluation matrices, or quadrant charts.
Key Concepts
1. Why Separate Evaluation from Generation

The central idea of this lesson is that evaluation and generation should often happen in separate conversations, not blended into one. The reasoning: when a conversation has already gone down a particular path of generating solutions, that same conversation may carry baked-in assumptions that bias any evaluation criteria generated afterward — the model may unconsciously build a rubric that flatters the options it already produced.

By generating evaluation metrics in a completely separate, independent conversation (without seeing the solution options first), the resulting metrics are more likely to be genuinely objective dimensions of what matters for the task, rather than criteria shaped by whatever solutions were already on the table.

2. Prompting for Metrics Without Solutions

The lecture demonstrates a specific prompting technique: explicitly telling the model to generate evaluation metrics, not solutions.

Example prompt structure:

"Give me five metrics to compare and contrast ways of accomplishing the following task. Don't list ways to accomplish the task. [task described below a separator, e.g., dotted lines]"

Key elements of this technique:

Explicit instruction not to generate solutions, only evaluation dimensions.
The task description is included, but framed as context for determining metrics, not as an instruction to solve.
A visual separator (like dotted lines) is used to signal that the task description below is reference material, not a command to act on directly.
3. Example: Metrics for the Camping Cake Problem

Using the "how do I bake a cake in the woods with limited tools" task, the model generated five evaluation metrics:

Ease of preparation
Cooking time
Consistency of results
Required supervision
Risk of burning the cake

The instructor notes this process can be extended indefinitely — generating more and more possible evaluation dimensions — and that this kind of structured evaluation framework generation is itself a valuable, otherwise costly service (the instructor compares it to paid consulting work that builds evaluation criteria and quadrant charts for businesses).

4. Reformatting Options Before Evaluation to Reduce Bias

Before running the evaluation step, the instructor takes an important extra step: reformatting all the generated solution options consistently, so that differences in formatting don't accidentally bias the evaluation. This ensures that any option judged "better" is judged based on its actual content, not because it happened to be formatted more clearly or persuasively than another.

5. Combining Generated Options with Generated Metrics

Once both independent outputs exist (a set of solution options, and a set of evaluation metrics), the final step combines them in a follow-up prompt:

"Evaluate these techniques using these metrics."

Both the reformatted options and the generated metrics are pasted into this prompt together. The result is a structured, dimension-by-dimension evaluation of each option — in the cake example, this produced assessments of the tinfoil oven, skillet cake, foil packet cake, and steamed cake methods, evaluated across all five metrics.

6. An Unexpected Benefit: Surfacing New Options

Interestingly, the instructor notes that running this fuller process (generating metrics, then evaluating options against them) surfaced new solution options that hadn't appeared in the original generation (e.g., a foil packet cake and a steamed cake that weren't part of the first round of options). This suggests that the added structure of evaluation criteria can itself prompt the discovery of additional, previously unconsidered solutions.

7. Extending Into Structured Outputs

The lecture notes that this technique can be extended further by asking the model to organize the evaluation into a table, evaluation matrix, or quadrant chart — the kinds of structured comparative outputs that are normally expensive, specialized consulting deliverables, now achievable directly and quickly.

Important Terminology
Separation of Evaluation and Generation

A prompt engineering practice in which the process of generating solution options and the process of generating evaluation criteria are done in separate, independent conversations, to avoid bias from assumptions baked into the generation process.

Evaluation Metrics

The specific dimensions or criteria (e.g., cost, time, risk, ease of use) used to compare and assess a set of generated options against each other.

Template Pattern

A prompting technique used to specify the desired output format (e.g., a consistent structure for listing metrics or options) so that generated content is easy to compare and reuse.

Reformatting for Bias Reduction

The practice of standardizing the formatting of multiple generated options before evaluating them, to ensure evaluation judgments are based on content rather than presentation differences.

Evaluation Matrix / Quadrant Chart

Structured, often visual formats for presenting a comparative evaluation of multiple options across multiple criteria, historically associated with professional consulting deliverables.

Main Ideas
Generating evaluation criteria in a separate, independent conversation from the one used to generate solution options produces more objective, less biased evaluation metrics.
A specific prompting technique — asking for metrics while explicitly instructing the model not to list solutions — is used to isolate the evaluation-criteria-generation step.
Reformatting all solution options consistently before evaluation prevents formatting differences from biasing the assessment.
Bringing independently generated options and independently generated metrics together in a final evaluation prompt produces a structured, dimension-by-dimension comparison.
This process can surface entirely new solution options that weren't part of the original generation step.
The technique can be extended into professional-style outputs like evaluation matrices and quadrant charts, achievable quickly and without specialized consulting.
Professional Insights

This lesson positions generative AI as a tool not just for generating solutions, but for generating the frameworks used to judge solutions — a distinct and often overlooked capability.

For an AI Subject Matter Expert, this has direct implications:

Evaluation frameworks (metrics, rubrics, comparison criteria) can themselves be AI-generated and refined, not just applied after being designed manually.
Separating generation and evaluation into independent conversations is a bias-reduction technique worth teaching explicitly, since it's not an obvious default behavior.
This capability directly parallels (and can reduce dependence on) paid consulting services built around comparative evaluation frameworks — a capability with real professional and cost implications.
Common Mistakes

Common mistakes related to this lesson's concept include:

Generating evaluation criteria in the same conversation used to generate the solutions, risking criteria that are unconsciously biased toward what's already been produced.
Comparing generated options without first standardizing their formatting, allowing presentation quality to influence judgment instead of actual content.
Treating a single round of evaluation-metric generation as final, rather than continuing to expand or refine the list of relevant dimensions.
Overlooking the potential for the evaluation step itself to surface new, previously unconsidered solution options.
Practical Takeaways

After completing this lesson, I can:

Generate evaluation metrics for a task in a separate conversation from the one used to generate solution options.
Use an explicit "don't list solutions, only metrics" instruction combined with a clear separator for task context.
Reformat multiple generated options consistently before submitting them for evaluation, to reduce presentation-based bias.
Combine independently generated options and metrics into a single evaluation prompt to produce a structured, criteria-by-criteria comparison.
Extend this technique into tables, evaluation matrices, or quadrant charts for a clearer, more professional final comparison.
