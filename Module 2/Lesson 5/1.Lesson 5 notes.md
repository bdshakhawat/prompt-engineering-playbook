# Module 2 – Lesson 5: Automated Search for Better Solutions

## 1. Lesson Overview

Generative AI can be used not only to produce a single solution, but to automatically generate many possible solutions and then evaluate them against objective criteria.

The central idea is:

> Generate many solutions → Test them → Score them → Rank them → Select the best solution.

This approach is especially powerful when:

- Generating a good solution is difficult or complex.
- Checking whether a solution is correct is relatively easy.
- Objective criteria can be used to compare multiple valid solutions.

---

## 2. Core Concept: Automated Search

Traditional prompting often follows this pattern:

```text
Prompt → AI → One Answer
=========================================================================================================================

A more powerful approach is:

Prompt
   ↓
Generate multiple solutions
   ↓
Test each solution
   ↓
Remove incorrect solutions
   ↓
Score valid solutions
   ↓
Rank solutions
   ↓
Select the best solution

The AI is therefore used as a generator inside a larger search-and-evaluation process.
3. Why Generate Multiple Solutions?

There is usually no reason to generate only one solution when generation is inexpensive.

For example, instead of asking:

Write one Python function that solves this problem.

We can ask the system to generate:

Solution 1
Solution 2
Solution 3
...
Solution 100

The solutions can then be tested automatically.

The best solution can be selected based on predefined criteria.

4. Generate → Test

The fundamental pattern is:

Generate → Test

For every generated solution:

Generate a candidate.
Test whether it satisfies the required conditions.
Reject candidates that fail.
Keep candidates that pass.

This creates a feedback loop.

Candidate Solution
       ↓
      Test
       ↓
 ┌─────┴─────┐
 ↓           ↓
Fail        Pass
 ↓           ↓
Reject      Keep
5. Generate → Test → Score

Passing the correctness test does not necessarily mean that a solution is the best.

Multiple solutions may all be correct.

Therefore, we can add a scoring stage:

Generate
   ↓
Test
   ↓
Score
   ↓
Rank
   ↓
Select

Possible scoring criteria include:

Accuracy
Speed
Efficiency
Cost
Simplicity
Robustness
Readability
Resource usage
Constraint satisfaction
6. Example: Software Development

Suppose we want AI to write a function.

Instead of generating one implementation:

AI → Code A

we can generate many:

AI → Code A
   → Code B
   → Code C
   → Code D
   → ...
   → Code 1000

Each implementation can then be tested.

Step 1: Functional testing

Does the code produce the correct result?

Step 2: Performance testing

How quickly does the code execute?

Step 3: Ranking

Among all correct solutions, which one performs best?

The final selection might therefore be:

Correctness + Performance
        ↓
   Best solution
7. Automated Search Loop

A general automated search system can be represented as:

START
  ↓
Generate candidate solution
  ↓
Test correctness
  ↓
Does it pass?
  ├── No → Reject
  └── Yes
       ↓
    Score solution
       ↓
    Store result
       ↓
Generate another candidate
       ↓
Repeat
       ↓
Rank candidates
       ↓
Select best candidate

This process can run hundreds or thousands of times.

8. Why This Is Powerful

The major advantage is that generative AI can produce solutions much faster than a human can manually create them.

If evaluating a solution is cheap and reliable, we can explore a large solution space.

For example:

1 solution
10 solutions
100 solutions
1,000 solutions
10,000 solutions

The system can search for better solutions without requiring a human to manually create every candidate.

9. Important Problem Characteristic

Automated search is particularly useful when:

The solution is difficult to generate but easy to verify.

This is one of the most important lessons from this module.

Good candidate problems
Code generation
Mathematical solutions with verifiable answers
Crossword solving
Optimization problems
Configuration generation
Data transformation
Algorithm optimization
Constraint-based problems
Less suitable problems

Problems where:

Correctness cannot be objectively evaluated.
Evaluation requires highly subjective human judgment.
There is no clear scoring function.
The generated candidates cannot be reliably tested.
10. Human Evaluation Alternative

Automation is not always necessary.

If automatic testing is difficult, we can still:

Generate many solutions.
Give them to humans.
Quickly eliminate weak solutions.
Rank the strongest candidates.

For example, 200 generated ideas could be reviewed by a group of people.

This creates:

Generate many
      ↓
Human evaluation
      ↓
Shortlist
      ↓
Rank
      ↓
Best solution

12. Key Principle

The lesson introduces a major shift in thinking:

Don't ask generative AI only for an answer. Ask how you can use generation as part of a search process.

Instead of:

"What is the best solution?"

think:

"Can I generate many candidate solutions,
test them objectively,
and select the best one?"

14. Key Terminology
Candidate Solution

One possible solution generated by the AI.

Verification

Checking whether a candidate satisfies correctness requirements.

Evaluation

Measuring the quality of a candidate.

Scoring

Assigning a numerical or categorical value to a candidate.

Ranking

Ordering candidates from better to worse.

Objective Criteria

Rules that can be used consistently to evaluate candidates.

Automated Search

Repeatedly generating and evaluating candidates to find a strong solution.

Search Space

The collection of possible solutions that could potentially be generated.

15. Main Takeaway

The important lesson is not simply "generate more."

The important lesson is:

Generate many candidates when generation is cheap, evaluate them using reliable criteria, and use the evaluation results to select better solutions.

This turns generative AI from a simple answer generator into a component of an optimization and search system.
